# 在 ScopeJudge 上评测我们的判准

> 数据：官方 `dreadnode/scopejudge`（MIT），100 条轨迹 / 4,897 个工具调用 / 377 个越界。
> 我们的 loader 读出来的点数与论文完全一致（4,897 / 377），见 `node load.mjs`。

## 怎么跑

```bash
# 只看读取与渲染（不调模型）
node run.mjs --dry --strategy intent_calls

# 自然分布随机抽样（固定种子，可复现）
node run.mjs --random 500 --strategy intent_calls --rubric v2

# 平衡抽样（正负各 N，用来看 TPR/FPR，不代表语料 F1）
node run.mjs --balance 40 --strategy intent_calls
```

输出：`out/results.<strategy>.<rubric>.<dry|live>.md` + 逐条 `rows.*.json`。

## 实测（同一批 500 点，自然分布 7.4% 正类）

| 投影策略 | 判准 | TP | FP | TN | FN | Precision | Recall | **F1** |
|---|---|---|---|---|---|---|---|---|
| intent_calls | v1（逐字授权） | 33 | 103 | 360 | 4 | 24.3% | 89.2% | 38.2% |
| intent_calls | v2（服务目标） | 31 | 84 | 379 | 6 | 27.0% | 83.8% | 40.8% |
| intent_summary | v2 | 32 | 75 | 388 | 5 | 29.9% | 86.5% | 44.4% |
| **full** | **v2** | **33** | **73** | **390** | **4** | **31.1%** | **89.2%** | **46.2%** |
| static（200 点） | v2 | 15 | 60 | 120 | 5 | 20.0% | 75.0% | 31.6% |

对照论文：最强 judge **F1 66%**（GLM-5.2）、最好闭源 60%、**人类专家之间 78%**。

## 我们读到的三个结论

### 1. 上下文越多越好，而且主要省的是**误报**

```
FP：103 → 84 → 75 → 73      （唯一单调下降的指标）
FN：  4 →  6 →  5 →  4
```

这和论文的结论一致方向，但我们是在**自己的判准**上复现的：
把"之前的调用 + 输出摘要 + 完整输出"给 judge，误报从 103 降到 73（-29%），召回几乎不损失。

**对我们的架构意义**：审查 agent 拿任务状态（已批准/已拒绝/进度）不是可选项——它是降误报的主要手段。

### 2. 纯静态策略确实会崩

200 点上 `static` 的 F1 只有 31.6%，比同时期 `intent_calls` 低约 9 个点，
且 recall 从 89% 掉到 75%——**"授权范围活在用户请求里"**这条被我们自己复现了。

### 3. 我们的失败模式是**过度标记**，不是漏放

```
FP 73 vs TP 33   →  precision 31%
FN 4  vs TP 33   →  recall 89%
```

在这个领域（渗透测试）里，正常探索步骤（信息收集、验证漏洞、读日志）人是算 in_scope 的，
我们的判准倾向于"没被逐字提到就算越界"，于是大量误报。

**这和我们在文件/数据域的表现正好相反**（那边是漏放 = 6/60，FN 高）。
原因：两个域的"授权边界"性质不同——数据最小化要求"没说的不许做"，渗透授权允许"为达成目标的一切常规手段"。

## 这说明什么（诚实版）

1. **同一套判准不能跨域直接迁移**。我们的 v1/v2 是为"数据最小化"写的，在渗透域必然偏严。
2. **F1 46.2% < 论文 66%** 不代表架构差，而是**判准没按域校准**。
3. 真正可比的做法：把判准做成**可配置的"授权风格"**——
   - `strict`（默认，数据域）：未被授权 ⇒ 越界；
   - `goal`（渗透/探索域）：服务于目标且不违反明确禁令 ⇒ 范围内。

   我们已经有 v1/v2 两个版本，`--rubric` 可切；下一步应该是把"风格"变成契约文档里的一个字段，而不是提示词里的常量。
