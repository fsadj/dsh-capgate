# 架构：为什么"读"必须是证明出来的，而不是猜出来的

> 这份文档解释一条设计约束，以及它为什么不能用"再加一条正则"的方式解决。

## 问题

命令是一段文本，效果藏在文本里：

```
Get-Content a.txt | Invoke-Expression     # 读？执行？还是任意代码？
cmd /c del x                              # 包装器里的删除
[IO.File]::Delete('x')                    # 没有"动词"的删除
robocopy src dst /MOV                     # 移动 = 删源
node clean.mjs                            # 脚本内部做什么？
```

任何基于词法的判定都是**不完备**的。补一个写法，下一个写法还在。这就是"补丁式修复"的死循环。

## 不变量（整套设计只有这一条是硬要求）

```
自动放行 ⇒  （这条命令可被证明为只读）
          ∨ （目标被用户原话点名  ∧  该效果类已被授予）
```

反过来：

```
不可证明 ⇒ 不许自动放行（问人 或 拒绝）
```

**任何组件都只能让判定更严，不能更松。** 这是整套架构的单调性来源：
加一层 LLM、加一条规则、加一个信号，都不会让"本不会放行的东西"被放行。

## 三层

### L1 结构证明（静态，可审计）

放行"读"的前提不是"看起来像读"，而是"能证明只读"：

1. 每个分段的首词都在**只读动词表**里；
2. 没有重定向 `>` `>>`；
3. 没有命令替换 `$(...)`、反引号、`iex` / `Invoke-Expression` / `-EncodedCommand` / `base64 -d`；
4. 没有包装器藏起来的第二层命令（`cmd /c`、`pwsh -c` 会被拆开再判）。

任一条不满足 → 降级为"未知效果" → 问人。

这条把"词法漏判"的后果从 **静默放行** 改成 **多问一次**。这是唯一可接受的失败方向。

### L2 类型化工具（by construction）

真正消灭"从文本猜效果"的办法，是让效果不需要被猜：

| 动作 | 现在 | 目标 |
|---|---|---|
| 删文件 | `pwsh("Remove-Item …")` 需要解析 | `fs.delete(paths[])`：效果是参数类型 |
| 发数据 | `pwsh("curl …")` 需要解析 | `net.post(url, body)`：效果是参数类型 |
| 写文件 | `write(path, content)` | 已有类型化工具 |

策略判在**类型化操作**上，不需要词法。raw shell 退化为 escape hatch：可以用，但**一律问人**。

这是唯一"架构正确"的方向：把安全性建立在接口设计上，而不是文本识别上。

### L3 LLM：只做"否决"和"翻译"，不做"授权"

模型能覆盖没见过的语法，但它错的方向恰好是最危险的（漏判）。所以：

| 用法 | 允许? | 理由 |
|---|---|---|
| 判断"这条命令能不能放行" | ❌ | 这是授权，错一次就是漏放 |
| 否决 L1 的"只读"证明 | ✅ | 只能让判定更严（单调） |
| 把命令翻译成"可能效果清单"，附在人工卡片上 | ✅ | 只增加人的信息量，不改变判定 |
| 枚举批量目标（供卡片展示） | ✅ | 同上 |

实测（60 条留出集，"模型一律说可以"的极端设定下）：

| 授权方式 | unsafe-allow |
|---|---|
| 让模型决定 | 20 / 60 |
| 分层（低风险层可放行） | 7 / 60 |
| 只允许它否决 L1 | **0**（否决只会增加拦截） |

## 为什么这不是"又一层补丁"

| 补丁式 | 本设计 |
|---|---|
| 增加正则覆盖新写法 | 增加**证明条件**；不完备只会多问 |
| 正确性依赖词表完备 | 正确性依赖单调性，不依赖完备性 |
| 漏判 = 放行 | 漏判 = 询问 |
| 每加一条规则都要重新论证安全性 | 任何新增组件只能收紧，无需重新论证 |

## 代价，以及怎么合法地降下来

raw shell 里的**变更操作**原则上都要问——这不是缺陷，是这套架构的价格。

降打扰只有三条合法路径，都不破坏不变量：

1. **减少需要走 raw shell 的变更**：提供类型化工具（L2）；
2. **增加"可证明无害"的覆盖面**：例如删除 git 跟踪的文件是可恢复的（`git ls-files` 命中 → 可证明可恢复 → 可放行）；
3. **把同一授权复用**：效果类摊销、同一命令复用（已实现）。

不合法的路径：让模型替你决定、把"看起来像读"当成读、把一次性批准推广成类授权。

## 诚实的边界

1. **运行时行为不可判定**：`node script.mjs` 里做什么，静态永远看不到 → 只能靠沙箱与审计，或让解释器也走类型化工具。
2. **L2 需要 dsh 侧的工具设计配合**：插件只能提供工具，不能废除 `pwsh`。
3. **沙箱是最后一道**：capgate 是决策层，不是执行层。越界写/删的最终阻止在 OS 沙箱。
4. **第三方工具语义不可信**：MCP 提供方可以把危险操作命名成 `read_file`。需要工具 allowlist 或签名，而不是相信名字。
