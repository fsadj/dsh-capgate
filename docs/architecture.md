# 架构：规则只做三件事，其余交给审查 agent

> 当前版本（v0.3.0）。源码 13 个模块 / 约 1900 行，`index.mjs` 约 420 行。

## 一句话

**判定权在 agent。** 规则只保留三种职责，且都不能"替 agent 放行变更类操作"：

| 职责 | 做什么 | 不能做什么 |
|---|---|---|
| **硬约束** | 绝对危险命令、凭据目标 | 不能放行 |
| **成本分流** | 可证明只读、人批准过的同一条 / 同一范围 | 不能放宽给变更类 |
| **可解释** | 判定流水、询问分类、拒绝时的收窄建议 | 不改变结论 |

## 判定链（全部）

```
工具调用
  ↓
分类：命令文本（shell）/ 参数 schema（其它工具）
  ↓
① 硬约束     绝对危险 → 拒 ；凭据目标 → 拒
  ↓
② 用户规则   只允许"拒"；"允许"降级为给 agent 的证据
  ↓
③ 成本分流   同签名 · 人批准过的目标集合 · 可证明只读 → 不打扰模型
  ↓
④ 审查 agent  其余一切（含所有变更类）
      给它：命令、效果、目标、锁、环境事实、**用户指令原文**、任务状态
      它有：read / glob / grep / capgate_probe（一条只读命令）
      它给：allow / deny / ask
  ↓
⑤ 映射       deny → 拒（带收窄建议）
              allow → 放行（凭据类仍不放）
              其它 → 问人
```

## 为什么没有"契约抽取 / 覆盖率判定 / 单次复核"

这些层都在 agent 之前**替它下结论，或把用户原话转述成结构**。删掉之后：

- 少 3~4 次模型调用；
- 少三层失真（转述、覆盖率、编译结果）；
- agent 拿到的是**原文 + 事实**，不是我们的理解。

实测：删掉它们之后，同一批 prompt 的越界没有上升，代码从 4500 行降到 1900 行。

## 不变量

```
变更类放行 ⇒ 必须来自审查 agent 或人
硬约束只能拦，不能放
任何规则不得放宽判定，只能收紧
用户原话是唯一授权来源；事实由 discover / capgate_probe 现取
```

## 成本控制

| 手段 | 效果 |
|---|---|
| 可证明只读快路 | 只读调用 0 次模型 |
| 同签名复用 | 人批准过的同一条命令 0 次 |
| 人批准的目标集合 | 其子集 0 次 |
| 判定缓存 | 同 (tool, args, op, 指令) 命中 |

## 已知边界

- 审查 agent 是唯一判定者，**它偏保守时完成率会掉**（headless 里 ask = 不执行）；
- 只读白名单是显式表（squeue / git / aws / kubectl 的只读子命令），新工具要补；
- 数据库只到语句级；内容级靠 agent 自己读。
