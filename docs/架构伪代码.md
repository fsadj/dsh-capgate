# capgate 架构伪代码（与当前实现对齐）

> 版本：与 `capgate-dsh` v0.2.0（214 条单测）一致
> 说明：伪代码按实现顺序写，`->` 表示返回判定结果；每一条都对应源码里的一个分支。

## 0. 判定结果只有四种

```text
ALLOW  放行（不弹卡）
ASK    问人（弹一张四段式卡）
DENY   拒绝（不执行，给最小替代）
NEXT   交给下一个监听器（不接管）
```

## 1. 前置：生效条件

```text
on tools/pre-execute(call):

    if 不是 capgate 模式               -> NEXT
    if 权限档 != capgate               -> NEXT   # 记一条 dormant 审计，避免"没拦"和"没在看"混淆

    sid = session.id
    # 评测开关：第一次工具调用时可跑纯 agent 评测（仅用于测量）
    if cfg.benchOut && !benchStarted: 后台跑评测并写文件
```

## 2. 绝对危险（词法唯一的否决权）

```text
    danger = ABSOLUTE_DANGER(rawText)          # 10 条：rm -rf /、mkfs、dd of=/dev/sd*、fork 炸弹、DROP DATABASE…
    if danger                            -> DENY  (审计 rule=danger.rule)
```

> 这是词法层**唯一**被允许做的事之一：拦"确定会毁东西"，不参与"这条命令是什么效果"的主张。

## 3. 归一化：调用 → 效果

```text
    (effect, klass, cwd) = classOfCall(call)
        # effect: {op, targets[], wildcard, opaque, elevated, sql?}
        #   op ∈ {read, write, delete, send, execute, other}
        #   targets[].kind ∈ {path, db, host}
        # klass:  {key, op, scope, sensitivity, cardinality}
        #   scope ∈ {workspace, outside:<root>, named:<...>}

    label = describeClass(klass)      # 面板/审计用的中文描述
```

## 4. 敏感路径（安全不变量，不交给模型）

```text
    if klass.sensitivity == 'sensitive':
        if scope != workspace        -> DENY
        else                         -> ASK      # 敏感路径永不摊销
        # 连续拒绝 N 次后转人工
```

> 凭据类永不因为"用户明确说了"而放行——纯 agent 评测里它确实会放，所以这条留在代码里。

## 5. 历史：同命令 / 已确认范围 / 来源事实

```text
    if signature.human_approved(call)             -> ALLOW   # 同一条命令，人批过
    if extent.covers(klass, targets)              -> ALLOW   # 人批准过的目标集合，子集放行
    if provenance.all_created(targets)            -> ALLOW   # 本任务内 agent 自己创建的文件
    if provenance.all_read(targets) && op==read   -> ALLOW   # 本任务内已读过
```

## 6. 读闸门（词法说读，也要语义同意）

```text
    if autoAllowReads && op==read && scope==workspace:
        gate = read_gate(call)
        if gate == 'ok'                           -> ALLOW
        # gate 的三档：
        #   off    : 直接 ok
        #   shadow : 记录 lex=read / sem=? / agree=?，仍然 ok（用来量词法错误率）
        #   on     : sem != read -> blocked（fail-closed）
```

`read_gate` 内部：

```text
    shape = shapeOf(command)                      # 字面量换占位符
    if shape in shapeCache                        -> return cached.op
    if seededOp(command)                          -> return 'read'   # 10 条精确只读命令
    else: op = compile_with_llm(call).op; shapeCache[shape] = op
```

## 7. 已授予的类

```text
    if class_granted(klass.key, ttl)              -> ALLOW
```

## 8. 锁（可以交给审查 agent 解释，但不是无条件否决）

```text
    locks = locksOf(klass, effect)
        # batch     : 通配 / 循环驱动 / 无 WHERE 的 DELETE、DROP、TRUNCATE
        # egress    : op == send
        # opaque    : 执行解释器/脚本，效果看不见
        # privilege : sudo/runas/提权前缀
        # sensitive : 凭据路径
        # unknown   : op == other

    if 'batch' in locks:
        r = review(call, locks, taskState)          # 见 §11
        if r.verdict == allow or r.clears('batch') and r.blast ok
                                                  -> ALLOW
        else                                      -> ASK
```

## 9. 引文（授权唯一来源）

```text
    evidence = evidenceFor(agent, klass, effect)
        # 只从 instruction 片段里取：用户粘贴的代码块/引用块不算授权
        # 目标必须逐字出现在用户原话里；动词要匹配
    if evidence.ok:
        if opaque:
            # 不透明执行永不给引文授权，除非脚本被静态检查证明无严重 API
            if scriptAudit.clean(script) && hash(script) unchanged -> ALLOW
        else:
            grant(klass);                          -> ALLOW
```

## 10. 语义引文（原文没逐字提到，但指代成立）

```text
    if not evidence.ok and op != 'other' and locks ⊆ {batch, egress, opaque, privilege}:

        entries = extract_intent(agent, instructions, recent_turns)
            # 模型从原话抽条目；每条必须带 quote
            # quote 必须能在用户 instruction 里定位（locateSpan），定位不到直接丢弃
            # residual=true → 不产生条目

        hit = literal_match(entries, targets)       # 前缀/通配，便宜
        if not hit and coverageMode:
            verdict = judge_coverage(instructions, entries, targets, locks)
                # 模型判断"这次调用是否被某个条目覆盖"，可解除意图类锁（要引文）
        if hit or verdict.allCovered and locksCleared:
                                                  -> ALLOW
```

## 11. 审查 agent（承重）

```text
    review(call, locks, taskState) = 起一个独立 subagent:

        toolFilter: allow = [read, glob, grep]      # 写/发/执行物理不可达
        maxDepth: 1
        outputSchema: {
            verdict:     allow | deny | ask
            action:      string
            facts:       string[]
            dataClass:   none | code | business | personal | credential
            blast:       { estimate, reversible: yes|no|unknown, note }
            consistency: match | mismatch | unknown
            clear:       [{lock, quote, why}]
            alternatives:[{label, op, scope}]
        }

        输入：工具 + 参数 + 效果 + 锁 + 探针事实 + 任务状态 + 用户原话逐字

        它可以：自己枚举（glob）、自己抽样（read）、自己搜（grep）
                自己判数据级别、影响面、一致性、给最小替代
        它不能：执行、写、发；也不能绕过策略的底线
```

## 12. 策略：只做映射与兜底

```text
    if r.verdict == deny or r.dataClass == credential or r.consistency == mismatch
                                                  -> DENY (带 alternatives)
    if r.verdict == allow and locks ∩ {sensitive, unknown} == ∅ and blast ok
                                                  -> ALLOW
    else                                          -> ASK
```

`blast ok` 的判定：

```text
    blast.reversible == 'no'                      -> 不放行
    blast.estimate > cfg.blastLimit (默认 1000)   -> 不放行
```

## 13. 询问（四段式）

```text
    askDecision(reason, label, display) =
        { kind: ask,
          reason,
          displayReason: { zh: "capgate: <动作>\n事实: …\n建议: …\n可替代: …" } }
```

## 14. 审批裁决（人点了按钮之后）

```text
on approval/request(req):

    if req.reason 以 "capgate:" 开头          -> NEXT    # 我们自己的卡，避免递归
    if 不是 capgate 模式                      -> NEXT

    if req 是沙箱升级请求:
        if class_granted && mode != 完全权限  -> ALLOW   # 接管，只出一张卡
        else -> 问人（capgate 文案），把结果回传给工具

    if pending.human_only || pending.sensitive -> NEXT

    outcome = await next()
    if allowed: grant(class); remember_signature(); record_extent(targets)
    else:       deny(class); record_decision(deny)
```

## 15. 任务状态（派生，不维护文档）

```text
buildTaskState(agent, decisions):
    instructions = 用户消息里的 instruction 片段（逐字、带 msgId）
    decisions    = 内存环形缓冲（最近 200 条：allow/deny/ask/grant + by + op + target）
    executions   = tool/call + tool/result（成功/失败）
    progress     = 按 op 统计的放行次数
    refused      = 最近被拒的目标
    relation     = 机器能算的：是否在既往批准范围内、是否命中被拒目标
    # 渲染成几百 token 的文本，连同用户原话一起交给审查 agent
```

## 16. 缓存与去重（省调用，不改判定）

```text
    shapeCache   : 命令形状 → op         （进程内 + 可落盘，重启后免调用）
    reviewCache  : (tool,args,op,指令摘要) → 判定 （进程内 + 可落盘）
    inFlight     : 同一判定的并发请求合并成一个子 agent 调用
    SEED(10 条)  : 精确只读命令，直接进 shapeCache（source = seed）
```

## 17. 不变量（写进测试）

```text
    1. 自动放行 ⇒ 可证明只读 ∨ 引文覆盖 ∨ 已确认范围 ∨ 来源事实
    2. 不可证明 ⇒ ASK 或 DENY
    3. 任何组件只能收紧：模型、规则、审查 agent 都不能让判定更松
    4. 两条底线不由模型决定：凭据永不、效果不可知必问
    5. 授权只来自用户原话；派生视图（任务状态/契约/缓存）不可扩权
```
